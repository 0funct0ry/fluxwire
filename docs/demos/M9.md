# M9 demo: folder runs

`make run`, **Open folder**, a copy of `fixtures/payments-api`. Point `baseUrl` (environment `local`) at a server that answers `POST /v1/auth/token`, `POST /v1/payments` (`201`) and `GET /v1/payments/{id}` (`200`).

1. **Open a run.** Right-click the *payments* folder → **Run folder** (or select it and press Cmd/Ctrl+Shift+R, or palette `run: run folder`). A ▶ *Run: payments* tab opens with the options bar: Concurrent/Sequential, Concurrency, Iterations, Env, Data, Filter, Bail.
2. **Sequential chain.** *payments* sets `run_mode: sequential` in `folder.flux.md`, so it runs in `seq` order and shares variables. Run the *auth* folder's `login`, then *payments*: `accessToken` and `paymentId` flow into later requests. Rows turn ✓ as they finish; each shows a timing bar placed on the run's timeline, test counts and milliseconds.
3. **Failures.** Make the server return `500` for one request: its row turns ✗ and expands to the assertion with expected vs actual. **Open request** opens it in a tab. **Re-run failed** runs only the failing requests.
4. **Concurrent run.** Select the collection root, choose **Concurrent**, set Concurrency to 32 and Iterations to 200 (or point the filter at a folder with many requests): progress repaints about every 100 ms and the list stays smooth (it is virtualized).
5. **Data file.** Choose **Data:** and pick a `.csv` (header row = variable names) or `.json` (array of objects). The run repeats once per row; iteration headers show the row values and `{{column}}` resolves in requests.
6. **Filter and bail.** Filter `tag:smoke`, `name:*refund*` or a name glob (comma-separated). **Bail** stops starting requests after the first failure; the rest show as skipped.
7. **Cancel.** Press **Cancel** during a slow run: in-flight requests are cancelled and the rest skipped.
8. **Export.** **Export JSON** and **Export JUnit** write the whole tree (secrets redacted). **Copy CLI command** puts the equivalent `fluxwire run <folder> --env … --concurrency … --filter …` on the clipboard (the command itself arrives in M10).
9. **History by run.** **View in History** opens the History panel filtered to this run (a `run …` chip; click it to clear).
