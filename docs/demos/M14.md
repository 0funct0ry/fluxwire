# M14 demo: packaging and distribution

```bash
make run
```

1. **About.** Open the palette and run `app: about Fluxwire`. The dialog shows the version, the commit (set by `make`; `unknown` for a plain `cargo build`), the licence and links to the site and source. Press `Report an issue`: the issues page opens in the browser.
2. **Updates.** Run `app: check for updates…`. The dialog shows the current version, "No check has run yet." and that the automatic check is off. Press `Check now`: the status becomes "Checking…" and then the result (a build newer than the latest release reads "You are on the latest version."; before the first release it reports the GitHub answer). Press `Turn on automatic checks` and look at `settings.toml`: `check_for_updates = true`, other lines unchanged. Turn it off again.
3. **Crash log.** Create `<config dir>/crashes/crash-9999999999.log` with any text (the config dir is `~/Library/Application Support/dev.fluxwire.fluxwire` on macOS), or trigger a real panic in a scratch build. Relaunch: a dialog says Fluxwire quit unexpectedly and offers `Open crash log`; it does not appear on the following launch. `app: open last crash log` opens the file again.
4. **Startup budget.**
   ```bash
   make build-release
   scripts/startup-timing.sh target/release/fluxwire
   ```
   The median of five runs prints and must be under 300 ms.
5. **macOS bundle.**
   ```bash
   make bundle-macos
   open dist/fluxwire-*-apple-darwin.dmg
   ```
   Drag `Fluxwire.app` to `/Applications` and launch it. Without `APPLE_*` variables the build prints that it is unsigned; Gatekeeper asks for confirmation on first launch. With the variables set it is signed, notarized and stapled.
6. **Linux bundle** (on Linux): `make bundle-linux`, then unpack `dist/fluxwire-*.tar.gz` and check `share/applications/fluxwire.desktop`, `share/mime/packages/fluxwire.xml` and the icons.
7. **CLI archive and checksums.**
   ```bash
   make cli-archive checksums
   ```
   `dist/SHA256SUMS` lists every archive.
8. **Installer script.**
   ```bash
   sh scripts/test-install.sh
   sh scripts/install.sh --help
   ```
   The test installs from a local fake release and proves that a tampered archive is refused.
9. **Release notes and tap.**
   ```bash
   scripts/release-notes.sh "" HEAD | head -30
   sh scripts/test-render-tap.sh
   ```
10. **Tag on a fork (manual).** Push `v0.1.0` to a fork: the Release workflow builds every target and creates a draft release with `SHA256SUMS` and attestations. After publishing, `curl -fsSL <site>/install.sh | sh` on a fresh Ubuntu container installs the CLI, and `brew install --cask 0funct0ry/tap/fluxwire` installs the app.
