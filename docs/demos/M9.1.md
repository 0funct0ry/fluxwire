# M9.1 demo

1. Build: `make build`. Start the server on both transports:
   `target/debug/fluxwire mcp serve --transport both --socket /tmp/fw.sock --root fixtures/payments-api`.
   stderr prints `listening on /tmp/fw.sock`; stdout stays silent until a client speaks.
2. In another terminal: `ls -l /tmp/fw.sock` shows `srw-------`.
3. Connect with the MCP Inspector over stdio:
   `npx @modelcontextprotocol/inspector target/debug/fluxwire mcp serve --root fixtures/payments-api`.
   *Tools* lists `ping` and `server_info`; calling `server_info` returns the version, format version `1`, transports, allowed classes `read, execute`, and the root.
4. Start a second server with the same `--socket`: it exits with "already in use by a live server".
5. Press Ctrl-C on the first server: the socket file is gone. `kill -9` it instead and start again: the stale file is replaced.
6. Run with `--allow read`: `execute` tools (none yet) would be hidden and refused; `server_info` shows `allowed_classes: ["read"]`.
7. `fluxwire mcp serve --transport tcp` exits 64 with a usage message.

## Claude Code

Put this in `.mcp.json` at the repository root:

```json
{
  "mcpServers": {
    "fluxwire": {
      "command": "fluxwire",
      "args": ["mcp", "serve", "--root", "."]
    }
  }
}
```

Run `/mcp` in Claude Code; `fluxwire` should show as connected with two tools.
