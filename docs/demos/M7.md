# M7 demo: scripting, expect blocks, and tests

`make run`, **Open folder**, `fixtures/payments-api` (work on a copy to keep the fixture clean). Select the `local` environment (Cmd/Ctrl+E) and point `baseUrl` at a server that answers `POST /v1/payments` with `201` and `{"id": "...", "status": "requires_capture", "amount": 4200}`.

1. **Trust.** Open *Payments → Create payment* and press Send. The banner says `This collection contains scripts. Scripts can send requests and read variables. Trust this collection?` and nothing is sent. Click **Trust**; the send goes ahead. Palette: `scripts: revoke trust for this collection` asks again next time.
2. **Pre script and the `lib/` import.** *Scripts* tab, **Pre**: `lib/sign.ts` is imported, `idemKey` is set with `crypto.randomUUID()`, and an `X-Signature` header is added. The `js`/`ts` button switches the block's language by rewriting only its fence. The server sees `Idempotency-Key` and `X-Signature`.
3. **Expect.** *Tests* tab, **Expect**: the `http expect` block with status chips (200, 201, 2xx…). **From last response** fills a missing block from the response. In the response pane, **Tests** lists `expect status`, `expect header Content-Type`, `expect body $.status`, `expect body $.amount`, then the `ts test` results; failures show expected vs actual.
4. **Capture.** `capture:` in the front matter sets `paymentId` and `location`. Environments panel → *Runtime variables* lists them (with **Clear**). Open *Get payment* and send: `{{paymentId}}` resolves.
5. **Console.** Add `console.log("hi", fw.response.status)` to the `ts test` block and send: the response **Console** tab shows time, level and text; the bottom dock Console (Cmd/Ctrl+J) logs the same as `[log] …`. Secrets set with `fw.vars.setSecret` show as `‹secret:name›`.
6. **Script errors.** Add `throw new Error("boom")` as line 3 of the `pre` block: Send is blocked, the response pane says `A pre script failed`, and Problems lists `S001 boom` at the original `.flux.md` line (not the stripped JavaScript line).
7. **Limits.** `while (true) {}` stops after 5 s with `S002`; `fw.sendRequest("payments/get-payment.flux.md", { vars: { paymentId: "p_1" } })` sends another request through the same engine.
8. **Types.** On open, `.fluxwire/types/fw.d.ts` is written; palette `scripts: regenerate fw.d.ts` rewrites it.
9. **Postman scripts.** Paste `pm.test("ok", () => pm.response.to.have.status(201));` into a `js test` block: it runs through the `pm` shim. `pm.visualizer.set(...)` fails with `Unsupported in Fluxwire: pm.visualizer.set`.
