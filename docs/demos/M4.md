# M4 demo: environments, variables, secrets, cookies, OAuth2

`make run`, **Open folder**, `fixtures/payments-api` (work on a copy if you want to keep the fixture clean).

1. **Environments panel.** Click the Environments icon in the status bar: `local` and `staging` from `environments/*.env`. Click one to make it active (the title-bar pill follows; Cmd/Ctrl+E opens the picker, which also offers *No environment*). Double-click, or *Edit*, opens the Environment tab.
2. **Edit variables.** In the tab click a name or value to type; every keystroke is written to `environments/<name>.env` (comments and untouched lines stay byte for byte; `git diff` shows only your lines). *Add variable* appends a row. Tick **Secret**: the row moves to `<name>.local.env`, which `.gitignore` excludes. If git tracks that file the tab shows a red warning with the `git rm --cached` command.
3. **Hover.** Open *Get payment* and hover `{{baseUrl}}` in the URL bar: value and source (`local.env, line 1`). Switch the environment (Cmd/Ctrl+E → staging): the hover and the URL that is actually sent change. Undefined names (`{{accessToken}}` before login) are red and underlined, and each is listed in **Problems** (V101).
4. **Completion.** In the URL bar type `{{` then a few letters: suggestions appear under the bar; Tab/Enter accepts, Up/Down move, Esc closes. Dynamic variables (`$uuid`, `$timestamp`, `$randomInt`…) are offered too. Works in the Params and Headers cells.
5. **Unresolved warning.** Send *Create payment* (it uses `{{idemKey}}`, set by a script in M7): the first Send only says `Unresolved variable: {{idemKey}}. Send again to send anyway.`; the second Send goes ahead.
6. **Secrets.** Mark `clientSecret` secret (it is also listed under `[secrets]` in `fluxwire.toml`): values show as `••••••••`; click to reveal for 10 s. Open *Login*, Copy as cURL (Cmd/Ctrl+Shift+C): `‹secret:clientSecret›`; the palette entry *copy as cURL (with secrets)* copies the real value. The Console (Cmd/Ctrl+J) never shows a secret, even when it ended up in a URL or body.
7. **Inheritance.** `payments/folder.flux.md` sets bearer auth and an `X-Merchant-Id` default header; requests in the folder inherit them (Auth tab: *Inherit*). Set `auth: none` (Auth tab *None*) on one request to opt out. `:id` segments in a URL take `path` front matter, else the variable `id`.
8. **Auth tab.** Pick Basic, Bearer, API key, Digest or OAuth2 and fill the fields (`{{variables}}` allowed); the `auth:` front matter is edited in place, prose untouched.
9. **Cookies.** Against a server that sets cookies, the response *Cookies* tab lists `Set-Cookie` values plus the jar entries for that host (`· jar`). Each environment has its own jar: the Environment tab has a *Cookies* section to edit values, delete one or *Clear cookies*. Add `persist_cookies = true` to `settings.toml` (in the Fluxwire config dir) to keep persistent cookies between runs.
10. **OAuth2, authorization code with PKCE.** On a request set Auth → OAuth2, grant `authorization_code`, *PKCE on*, token URL, authorization URL, client ID (and secret if needed) and optionally a redirect port. Press **Fetch new token**: the browser opens, you log in, the redirect lands on `127.0.0.1` and the tab reports the token with its expiry. Sending the request now carries `Authorization: Bearer …`; the token refreshes automatically before it expires (when the server issued a refresh token). The mock OAuth server in `crates/fluxwire-http/tests/m4.rs` is a handy local target.
11. **Runtime variables.** The Environments panel lists runtime variables with **Clear** (scripts set them from M7).
12. **Restart.** The active environment is remembered per workspace.

`{{process.env.X}}` stays unresolved in the GUI until `allow_process_env = true` is set in `settings.toml`.
