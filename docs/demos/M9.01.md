# M9.01 demo: workspace lifecycle

1. **Welcome.** Start with no saved state. The window shows only *Open workspace…*, *New workspace…* and recent workspaces. No docks, no environment picker.
2. **New workspace.** Click *New workspace…* (or Cmd/Ctrl+Shift+N). Name `demo`, pick a location, check the path preview, Create. Only the `demo/` directory exists; the center says "demo has no collections".
3. **New collection.** Click *New collection…*, name it `Payments`. `demo/payments/` holds `fluxwire.toml`, `collection.flux.md`, `environments/` and `.gitignore`; the collection is selected and its `collection.flux.md` opens as a preview tab. Cmd/Ctrl+N now creates a request in it.
4. **Add existing.** *Add existing collection…* on a folder outside `demo/` offers to open that folder as the workspace; on a plain folder inside it asks to make it a collection.
5. **Single-collection workspace.** Open `fixtures/payments-api`: *New collection…* and *Add existing collection…* (in the workspace node's … / right-click menu) are disabled with the tooltip about nesting.
6. **Close.** Make an unsaved edit, press Cmd/Ctrl+Shift+W (or "Close workspace" in the workspace node's … / right-click menu): the confirm lists the unsaved request with *Save all and close*, *Discard and close*, *Cancel*. Start a slow folder run: the confirm offers *Stop and close*.
7. **Relaunch.** The welcome view shows (closing cleared the last workspace); opening the workspace again restores its tabs.
