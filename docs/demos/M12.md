# M12 demo: OpenAPI two-way sync (app only)

The steps below use the Fluxwire app. The one thing the app cannot do is edit the OpenAPI file itself, because the spec is owned by someone else in real use; steps 4 and 9 change it in any text editor to stand in for an upstream change.

```bash
make run
```

1. **Create a Workspace for the demo.** Run `workspace: new` from the command palette, name it `pets-demo`, and choose an empty folder such as `/tmp/pets-demo`.
2. **Import with a Spec link.** Run `import…` from the palette (or drop `fixtures/import/openapi/petstore.yaml` onto the window). Confirm the detected source is OpenAPI, choose the Workspace root as the target, tick "Create a Spec link to this document", review the preview tree and report, and press Import. Because the Workspace is empty, the import creates one collection folder `petstore/` holding the `petstore/` Folder with its `pets/` requests and the spec copy `petstore/petstore/petstore.yaml`.
3. **In sync.** The status bar shows `OpenAPI ↓0 ↑0`. Click it (or run `sync: open`): the Sync tab lists `petstore/petstore.yaml` with `0 incoming, 0 outgoing, 0 conflicts`, and Pull and Push are disabled.
4. **Change the spec (outside the app).** In `<collection>/petstore/petstore.yaml`, change `summary: Create a pet` to `summary: Add a pet` and save. The status bar becomes `↓1 ↑0` without any action.
5. **Change a request in the app.** Open `Get a pet` in the tree, rename it to `Fetch a pet` in the Request name field, and save. The status bar becomes `↓1 ↑1`.
6. **Review.** In the Sync tab, the list shows `↓ createPet name` and `↑ getPet name`. Untick the `↑` row, then tick it again; the mark toggles without changing any file.
7. **Pull.** Press Pull. The notice reads `Pulled: 1 file(s) updated…`, `Create a pet` is renamed to `Add a pet` in the tree, and the counts become `↓0 ↑1`.
8. **Push.** Press Push. The notice reads `Pushed: spec updated`, and the counts become `↓0 ↑0`. Open `petstore/petstore.yaml` in a text editor: only the two `summary:` lines changed and comments are intact.
9. **Conflict.** Change `summary: Add a pet` to `summary: Spec side` in the spec file and save. In the app, rename the `Add a pet` request to `App side` and save. The status bar shows `⚠1`, and the Sync tab shows a conflict card with Base, Spec and Collection panes. Pull and Push are disabled.
10. **Resolve.** Press Take collection. The card shows "Taking the collection", and Push becomes available. Press Push; the spec summary becomes `App side` and the counts return to zero. (Take spec instead would be applied by Pull.)
11. **Exclude a change.** Make another small request rename, untick its row in the Sync tab, press Push, and confirm the spec did not change and the row is still listed.
12. **Deleted operations.** Delete the `Delete pet` request from the tree. The Sync tab shows `↑ deletePet deleted` and the choice "Deleted operations: Mark deprecated / Remove". Pick Mark deprecated and Push; the spec gains `deprecated: true` on that operation.
13. **Needs manual edit.** Rename a request whose parameter in the spec is defined through `$ref`. After Push, the change is listed under "Needs manual edit" with its spec location and the spec is not changed for it. (The petstore fixture has no such parameter; add one by hand if you want to see this.)
14. **Palette.** Type `sync:` in the palette: `sync: open`, `sync: refresh`, `sync: pull`, `sync: push`.
15. **Themes.** Switch to One Light with `theme: select…` and check the Sync tab stays readable.

Not available in the UI yet: linking an existing Collection that already has a `fluxwire.toml`, typing a custom value for a conflict (Edit… only agrees on the collection's value), pushing changes to method, path, status or tags, URL sources and Swagger 2.0. See ADR-021.
