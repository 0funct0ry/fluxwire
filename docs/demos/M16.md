# M16 demo: GraphQL

Run the app with `make run`. The steps use the public Countries API, `https://countries.trevorblades.com/graphql`.

## 1. Create a GraphQL request

1. Open or create a collection and add a request named `Countries`.
2. Replace the file with:

   ````markdown
   ```http
   POST https://countries.trevorblades.com/graphql
   ```

   ```graphql query
   { __typename }
   ```
   ````

3. Save. The front matter gains `requires: [graphql]` automatically, and a **GraphQL** sub-tab appears after Settings.

## 2. Introspect and build a query with the builder only

1. Open the **GraphQL** sub-tab and press **Introspect** (or run `graphql: introspect schema`). The toolbar reports
   `Schema loaded: N types.` and `.fluxwire/graphql/` in the collection gains one JSON file per URL and environment.
2. Press **Builder**. Check `countries`, then `name` and `capital` under it. The `graphql query` block is rewritten after
   every click, and checking an object field adds a default sub-field so the query stays valid.
3. Check `country`. Its required argument `code` is filled at once (`country(code: "")`) and listed under
   **ARGUMENTS · sent** with a red `required` label; the returned fields are listed under **FIELDS · returned**. Type
   a value in the input (a bare word is quoted for `String` and `ID` arguments), or press **$ variable** to use a
   variable: the operation declares it and a `json variables` block is created with a placeholder, which you then
   edit. A half-typed value never changes the query, and a variable typed as `$name` is added to the variables
   block when you leave the input. Send with **Send** or `Cmd/Ctrl+Enter`.
   The **Variables** pane under the query has a **Table** and a **JSON** view (a key/value table, or the raw
   block) and a handle on its top edge: drag it to change the height.
   Uncheck every field: the query stays as `query Name { }` and the tree stays open. A blank query block gets a
   `query { }` stub the first time the sub-tab shows it.
   Use the arrow beside an object field to open it without checking it, and the filter box to find a field, for
   example `email`, several levels down.
4. Type in the query editor: field names, argument names, enum values and `$variables` complete from the schema, and
   unknown fields or missing required arguments are listed under the editor (click a line to jump to it).
5. Edit the query text by hand. The builder tree follows it whenever the query parses; with fragments or several
   operations it says what it cannot show and leaves the text alone.

## 3. Send and read the response

1. Press `Cmd/Ctrl-Enter`. The response viewer has **Data** and **Errors** chips next to Pretty and Raw.
2. Break the query (for example ask for a field that does not exist). With the server's errors, the GraphQL tab lists
   them under the editors; click one to move the caret to its line and column in the query.
3. Add a Tests expectation:

   ````markdown
   ```http expect
   200

   { "countries": [ { "name": "Norway" } ] }
   ```
   ````

   An expected object that names neither `data` nor `errors` matches against `data`, partially.

## 4. Run from the CLI

```bash
fluxwire run countries.flux.md
```

The run exits `0`. A build without GraphQL support refuses the same file:

```bash
cargo build -p fluxwire-cli --no-default-features
target/debug/fluxwire-cli run countries.flux.md   # exit code 66, diagnostic F401
```

## 5. Import

`fluxwire import postman|insomnia|hurl <file>` now writes GraphQL requests as `graphql query` and `json variables` blocks
with `requires: [graphql]` instead of a JSON body.
