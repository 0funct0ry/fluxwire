Your API requests belong in your repo.

Fluxwire is a native, GPU-rendered client for REST and WebSocket APIs. Every request is a small text file you review in pull requests, run in CI, and never upload anywhere.

Reviewed like the code it tests.

Each request is a Markdown file: a few lines of front matter, a sentence or two of explanation, and fenced blocks for the request, the response you expect, and any scripts. The request is written as a plain HTTP message, the way the RFCs and your terminal show it.

It renders as documentation on GitHub, coding agents read and write it without special instructions, and edits from the app touch only the lines that changed.

Everything an API client needs, nothing that phones home.

Requests, environments, secrets, and history stay on your machine. There is no account to create and no telemetry to turn off.

Native and GPU-rendered

Fluxwire is written in Rust on GPUI, the framework behind the Zed editor. It opens in a blink, scrolls a 50 MB JSON response without stutter, and searches thousands of requests as fast as you type.

If you use Zed, the keybindings, panels, command palette, and themes will feel familiar. Zed themes load as they are.

An open format built to grow

The format is documented and has no Fluxwire-only syntax: Markdown, a small YAML header, and fenced blocks whose labels say what they do. A published schema lets editors and agents check their work.

New protocols slot in as new kinds of block. GraphQL, gRPC, MCP, and Server-Sent Events are on the roadmap, and a file that needs a newer Fluxwire says so instead of running the wrong way.

```mcp
tools/call search_payments
Server: {{paymentsMcpUrl}}
```

Scripts in JavaScript or TypeScript

Pre-request scripts, post-response scripts, and tests run in an embedded, sandboxed engine. Share helpers from a lib/ folder. Postman scripts you import keep working through a compatibility layer.

import { sign } from "lib/sign.ts";

fw.request.headers.set("X-Signature", sign(fw.request.body.text()));
fw.test("is authorized", () =>
  fw.expect(fw.response.json().status).toBe("authorized"));

The same runs in CI

The app and the command line share one execution engine. Run a folder concurrently or in order, feed it a CSV of test data, and report as JUnit for your pipeline. A static, GUI-free build fits in any container.

Two-way OpenAPI sync

Link a folder to a spec. Pull new operations and parameters into your requests; push renamed requests and new parameters back into the spec. Changes on both sides are merged field by field, conflicts wait for you, and YAML comments survive.

Bring what you already have

Import collections and environments in one step. Every import ends with a report of anything that did not convert cleanly, so nothing disappears quietly.

WebSockets, history, and docs

Keep saved messages next to a WebSocket request and watch frames as they arrive. Every send is stored in a local history you can search, diff, and restore. Write Markdown docs beside your requests; they render in the app and on GitHub.

Install.

brew install --cask 0funct0ry/tap/fluxwire

Or download the signed .dmg for Apple silicon or Intel.

curl -fsSL https://0funct0ry.github.io/fluxwire/install.sh | sh

Installs to ~/.local and verifies the checksum. Archives for x86_64 and arm64 are on the releases page.

Download fluxwire-x86_64.msi

The installer adds fluxwire to your PATH and opens .flux files in the app.

curl -fsSL https://0funct0ry.github.io/fluxwire/install.sh | sh -s -- --cli-only

Installs fluxwire-cli, a static binary with no GUI dependencies, for containers and runners.
