# Changelog

## Unreleased

### Added
- **Scenarios, playbook and CI smoke (M9.8).** `dev-mcp` builds add `ui.run_scenario` (YAML scenarios from `fixtures/scenarios`, or inline, with `assert` on `ui.state`, `assert_find`, `click_element`, `screenshot` and `audit` checkpoints and `wait_event`; the report names the failing step with expected and actual value, `ui.state` and a screenshot), `ui.record` (a session becomes a scenario) and `ui.events` (a replay buffer of run, frame, notice, console and generation events, also pushed as MCP logging notifications). `fluxwire mcp scenario FILE --socket PATH` runs a scenario against a running app for CI. Scenarios ship for M2, M3, M4, M7, M8 and M9; `docs/agent-testing.md` has the `.mcp.json` setup, tool catalog, safety model and bug-hunting playbook; `.claude/skills/ui-test` drives it from Claude Code. CI gains `smoke-headless`, `smoke-ui-linux` (xvfb) and `smoke-ui-macos` jobs. See ADR-009.
- **UI audit (M9.7).** `dev-mcp` builds add `ui.audit`, a linter over the semantic tree and theme tokens with rules UX101 (clipped or truncated text without a tooltip), UX102 (overlapping siblings), UX103 (target below 20 points), UX110 (WCAG AA contrast, per element and per theme pair), UX120 (hard-coded colour), UX130 (action with no binding or palette entry), UX131 (keyboard reachability and focus ring), UX140 (missing empty, loading or error state fixture) and UX150 (frame and input-to-paint latency). Findings carry rule, severity, message, element ids, bounds and a suggested fix; `states`, `themes` and `sizes` sweep a matrix. `ui.walkthrough` runs a list of steps (now including `click`) and reports time, keystrokes, clicks and notices per step and in total. See ADR-009.
- **Screenshots at a given state (M9.6).** `dev-mcp` builds add `ui.screenshot` (the window or one element by id, after applying a named state from `fixtures/ui-states` or a list of steps; waits for the UI to settle, masks volatile text, returns the PNG with `ui.state`, size, scale and capture tier), `ui.screenshot_all` (a labelled states x themes x sizes matrix that restores theme and size), `ui.set_theme` (not saved to settings) and `ui.resize` (`default`, `compact`, `min` or `WxH`). Capture uses `screencapture` on macOS and `grim` or ImageMagick `import` on Linux; a missing permission or tool yields an actionable error instead of a blank image. Nine states ship in `fixtures/ui-states`. `ui.capture_prototype` is removed. See ADR-009.
- **Semantic UI tree (M9.5).** `dev-mcp` builds add `ui.tree` (stable ids, roles, labels, enabled, bounds, visible, clipped, focused and z-order; filter by subtree, role or visibility), `ui.find` (by label, role or text) and `ui.click_element`, which runs the click handler the element registered (gpui 0.2.2 cannot inject pointer events). The `dev_id` helpers compile to plain `on_click` without `dev-mcp`. M9.5 tags the title bar, status bar, toolbar and request tabs; other controls follow. See ADR-018.
- **UI actions and input over MCP (M9.4).** `dev-mcp` builds add `ui.list_actions` (name, label, binding, context, palette flag, and whether each action is enabled now), `ui.invoke_action` (by `fluxwire::Send`, bare `Send` or alias; an unknown or disabled action is an error, never a silent no-op), `ui.command` (`open_file`, `set_url`, `select_tab`, `choose_environment`, calling the same Workspace methods as the UI), `ui.key` (`cmd-enter`, chords separated by spaces), `ui.type_text`, `ui.wait_for_idle` and `ui.wait_for` (a JSON pointer into `ui.state`, with a timeout). Input results carry the new `generation` and any notice. `ui.click` and `ui.scroll` are registered but return an error: gpui 0.2.2 has no public pointer-event injection. See ADR-009.
- **In-app MCP host and state snapshot (M9.3).** Builds with `--features dev-mcp` (off by default and in release builds, which contain no MCP server code or flags) accept `fluxwire --mcp-socket [PATH]` and `--mcp-stdio` and serve the `fluxwire-agent` tools from inside the running app. `ui.*` calls cross to the GPUI thread over a channel with a reply and a 5 s timeout; tools never touch GPUI entities off-thread. New `ui` tools: `ui.state` (a serde snapshot of the Workspace, tabs, docks, Problems, Console, active response, runs, modal, dialog, notice, trust prompt, focus, window, theme and a `generation` that increases on every change), `ui.open_workspace`, `ui.open_request`, and `ui.capture_prototype` (window region plus `screencapture -x -R` on macOS, with a clear Screen Recording error). gpui 0.2.2 has no render-to-image; recorded in ADR-009.
- **Engine tools over MCP (M9.2).** `fluxwire mcp serve` now serves read tools (`list_collections`, `list_requests`, `read_request`, `diagnostics`, `list_environments` (names only, never values), `resolve_vars`, `history_query`), write tools (`write_request` with span edits or canonical-formatted content, `fmt`; both return a diff and take `dry_run`; paths outside `--root` are refused) and execute tools (`send_request`, `run_folder` returning the `report::to_json` report, `cancel`). Results are redacted with the run's secrets. Scripts run only in a Collection trusted in `trust.toml`, which MCP reads and never writes; an untrusted Collection's script requests are not sent and say so. Scope, net, settings and trust assembly moved to the GPUI-free `fluxwire_runner::prepare`, which the app now uses too. History migration 4 adds `origin`; rows written through MCP are tagged `agent` and the History table shows the tag. See ADR-009.
- **MCP core and transports (M9.1).** New `fluxwire-agent` crate (rmcp, no GPUI) and `fluxwire mcp serve` (`--transport stdio|unix|both`, `--socket PATH`, `--allow read,write,execute` default `read,execute`, `--root PATH`; the same keys under `[mcp]` in `fluxwire.toml` or `settings.toml`, flags win). The unix socket is mode 0600, a stale file is replaced, a live one refused, and it is removed on exit; there is no TCP listener, and Windows gets stdio only. Tools are classed (read, write, execute, ui): a tool outside the allowed classes is neither listed nor callable. First tools: `server_info` and `ping`. Defines the `UiBridge` trait for the in-app host (M9.3). See ADR-009.
- **New request dialog (M9.07).** `New request…` (Cmd/Ctrl+N, tree menu, empty states) creates a request in one step: type (HTTP, WebSocket or From cURL), name with a filename preview, `Save in` picker, method and URL or a pasted cURL command with a live summary and warnings, and Options (description, initial body type). The inline row is kept as `Quick request` (palette: `workspace: quick request`); `New WebSocket request` is now a type in the dialog. cURL import reuses the paste parser, which now ignores `-o`/`--proxy`-style flags with a warning, uses only the first URL and rejects `-d @file`. See ADR-017.
- **Code editor revamp (M9.06).** One reusable `CodeEditor` replaces every multi-line editor: Body, "Open as text", Scripts, Tests, the WebSocket composer, Environment bulk edit and the new Docs editor. It adds IME and dead keys, auto-closing pairs and selection surround, smart indent, Tab/Shift+Tab block indent, comment toggling, move/duplicate/delete line, Home toggling, soft wrap, go to line, jump to matching bracket, and renders only the rows in view. Completions: `fw` and `pm` members and variable names in Scripts and Tests, `{{` variables everywhere, front matter keys, fence info strings and `expect` helpers in "Open as text", and fence languages, links and heading anchors in Markdown. The Docs sub-tab has a rendered *Preview* (default, read-only: headings, styled text, links, lists, tables, code blocks) and a *Source* mode that edits prose only (front matter and request blocks are read-only and can never change). New: `request: format body` (JSON and XML), `[editor]` settings with per-language overrides, and `editor:` actions. See ADR-016.
- **Themes and theme switcher (M9.05).** 53 bundled themes (Fluxwire's One Dark/One Light plus 51 ported from microterm), a second theme format (microterm TOML with OKLCH-derived UI and syntax colours, optional `[ui]`/`[syntax]` overrides) next to Zed JSON, `theme: select…` with live preview (Esc reverts, Enter keeps), a `~` palette/quick-search prefix, and a `theme` key in `settings.toml` written without touching other content (a malformed file is never overwritten). The app follows the OS appearance only while no theme is set; `theme: toggle` stays session-only. The theme model lives in `fluxwire-format::theme` (ADR-015).
- **Command palette curation (M9.04).** The palette lists only curated commands; key-bound-only actions (`input:`, `modal: dismiss`, send, save, tab switching, response sub-views…) are hidden but keep their bindings and `keymap.toml` support. `command palette: toggle` closes an open palette; labels renamed (`view: toggle sidebar`, `view: toggle console`, `keymap: show`, `settings: show`, `scripts: trust collection`, `scripts: revoke trust`) with the old ones kept as aliases; `environment: delete…` needs a selected environment. New: `workspace: new collection`, `workspace: copy path`, `keymap: edit` (in-app keybinding editor: edit, clear, reset, conflict warning; writes `keymap.toml` preserving comments).
- **History viewer (M9.03).** History is a workspace-level tab (Cmd/Ctrl+Shift+H): a sortable, filterable, virtualized table with resizable columns, folder-run groups, an inline detail pane (request, response, error and phase for failed sends), a stats strip (count, success rate, p50, p95), pin, notes, multi-select, diff, *Compare to previous*, restore, and JSON/CSV export. The left-dock History panel is now a navigator (timeline, saved views, requests with counts) whose items open the tab with a filter. Pinned entries survive retention and Clear. New actions: `history: open`, `history: focus search`, `history: pin`, `history: export`. Store migration 3 adds `pinned` and `note`.
- **Environment management (M9.02).** Environments are workspace-level (`<workspace>/environments/`, one active environment); collection-level environments are deferred. Environment switcher overlay (title-bar pill, Cmd/Ctrl+E) with *New environment…*, *Create environment “q”*, and *Manage environments…*; Environments panel; New environment dialog (Start from, Set as active); validated rename; delete confirm listing files.
- **Environment editor.** Key–value table with live Name/Value inputs, Secret lock, Source, drag reorder, filter, bulk edit, validation (E101–E106), document undo, dirty state, Cmd/Ctrl+S, close confirm, and an external-change banner. Sends use unsaved values.
- **One active environment per workspace,** remembered in the session (including an explicit "No environment").
- **Shared text input.** Mouse selection, per-OS keyboard table, clipboard, undo, IME and dead keys, context menu, masked and read-only variants; the code editors gain selection, clipboard, and undo.
- New actions: `environment: edit active`, `environment: manage`, `environment: new…`, `environment: rename…`, `environment: duplicate`, `environment: delete…`; the `@` quick-search prefix lists the workspace's environments.

### Fixed (post-M9.02 review)
- Tab moves Name → Value → next row in the environment editor; E106 uses `git check-ignore` (so `*.env` counts) and clears on its own; the Environments panel lists environments only (no repeated heading or variables), has a per-row menu (right-click and "…") with Copy as .env / Postman JSON; the dirty dot uses the `modified` colour in the tab and panel; Secret is a checkbox with an eye button that reveals for 10 s.

### Changed
- Environment files are written only on save, byte-preserving (comments, order, quoting kept).
- `OpenEnvironment` is now `EditActiveEnvironment` (old names still work in `keymap.toml`).
